# packages/db (`@wambito/db`)

Drizzle schema, SQL migrations and row-level security for Postgres.

## Entry points

- `src/schema/domain.ts` (app tables), `src/schema/auth.ts` (Better Auth tables, generated by
  `pnpm --filter @wambito/api auth:generate`).
- `drizzle/*.sql` + `drizzle/meta`: migrations; `drizzle/0001_rls.sql` holds the RLS policies.
- `src/migrate.ts` (`runMigrations`), `src/bootstrap.ts` (`ensureAppRole`, `APP_ROLE`),
  `src/client.ts`, `src/orm.ts`, `src/testing.ts` (test Postgres).
- Scripts: `pnpm --filter @wambito/db generate` (drizzle-kit), `migrate`, `bootstrap`.

## Rules

- Migrations run as the admin/owner role, never as the runtime role. The API connects as
  `lukas_app` (`NOSUPERUSER NOBYPASSRLS`), so every user table needs RLS and a grant to it.
- `lukas_app`, database `lukas` and admin `lukitas` are part 2b names: don't rename.
- Add migrations with drizzle-kit; never edit an applied one.
- In production `docker compose run --rm migrate` (`deploy/personal/up.sh`) runs bootstrap +
  migrations.

## Test

- `pnpm vitest run --project @wambito/db` (testcontainers: Docker, or `WAMBITO_TEST_DB=local`).
